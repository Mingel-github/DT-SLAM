# DT-SLAM 几何候选库、当前轻量方法与实验结果说明

日期：2026-08-02  
用途：供项目成员和其他 AI 独立理解当前几何路线；本报告不替代各阶段原始 SPEC、RESULT、CSV 和轨迹文件。

---

## 一、执行摘要

DT-SLAM 的目标是：

```text
ORB-SLAM2 RGB-D
+ YOLOv8-seg 处理已知动态类别
+ 类别无关几何证据补充未知动态物体
→ 减少动态观测对定位和静态地图的污染
```

项目最初调研的几何候选库很广，包括多视图深度一致性、深度区域聚类、配准残差、自由空间、稠密/稀疏光流残差、点相关图、多刚体运动分割和三维拓扑投票等。候选库的作用是提供研究路线和对照方法，不是要求把所有论文组件同时装进一个系统。

经过逐阶段 shadow 实验，当前实际冻结的轻量几何方法是：

> **基于 RGB-D 相机自运动补偿的稀疏 LK 光流残差候选过滤，以及 ORB-SLAM2 Tracking/MapPoint 写入保护。**

它不是“直接把 LK 位移大的点判为动态”，而是：

1. 用双向 LK 找到当前 ORB 特征在上一成功帧中的位置；
2. 用上一帧深度、相机内参和当前初始位姿，预测该三维点在静态世界中应该出现的位置；
3. 计算实际位置与静态预测位置之间的残差；
4. 经过 LK、深度、投影、语义和帧内尺度检查后，产生高残差候选；
5. 在严格的 fail-open 条件下，清除少量局部地图关联，并阻止部分候选创建新 MapPoint。

当前工程链路已经真实执行，但实验尚未证明该候选主要来自未知动态箱子，也没有证明其能稳定改善 ATE/RPE。TUM walking 上完整系统已接近相关文章的 1.5–2 cm 水平，几何增量很小；Bonn moving/placing box 上则与完整对象/区域方法存在明显差距。

## 二、任务边界

类别无关几何模块最初希望输出：

\[
\mathcal D_t^{\mathrm{feat}}
\quad\text{和}\quad
M_t^{\mathrm{depth}},
\]

分别用于：

- 过滤动态 ORB 特征，保护相机位姿和稀疏 MapPoint；
- 过滤动态深度像素，减少未来稠密地图中的残影与拖影。

当前实际完成的是第一项的实验版本：

```text
高残差 feature candidate
→ Tracking association removal
→ MapPoint admission veto
```

当前尚未完成：

```text
可靠未知动态对象分组
完整动态深度 mask
G1-D 稠密深度过滤
动态对象轨迹或对象级 BA
```

始终保持的工程边界：

- 不修改 `Optimizer.cc` 和 g2o；
- 不新增第三次 `PoseOptimization()`；
- 不修改 YOLO 模型和推理逻辑；
- 不重写 LocalMapping、LoopClosing 或 BA；
- 不引入 TSDF、3DGS 或对象级后端。

## 四、项目实际走过的路线

### 4.1 G0：深度一致性证据

实现过：

```text
单参考/多参考 dense depth warp
+ z-buffer
+ signed depth residual
+ valid/positive/negative/unknown 分离
```

得到的积极结果：

- 坐标系、位姿方向、深度尺度和 z-buffer 链路得到验证；
- 能在运动或遮挡区域产生深度不一致证据；
- 明确了“无深度/未覆盖”不能解释成静态。

未解决的问题：

- 位姿误差、遮挡边界和深度噪声也会产生相同 residual；
- residual 更像 scene inconsistency，不直接等于 object motion；
- 单纯从所有 positive seed 出发沿深度连续性传播，会覆盖大型墙面、地板或桌面连通区域。

### 4.2 G0-3/G2 区域路线

测试过：

- 固定绝对深度差 flood fill；
- 相对深度 flood fill；
- running-mean/区域支持率修补；
- full/low-resolution region partition；
- 简单 depth component；
- normal＋distance 分段；
- Ji 2021 K-means/reprojection baseline；
- 多参考投票与低分辨率近似。

核心负结果：

> **局部深度连续不等于同一运动对象。**

低层 seed 存在，但简单区域传播无法可靠恢复未知动态对象，且静态背景误扩张明显。因此没有把像素区域 mask 接入真实 SLAM，也没有开放 G1-D。

### 4.3 稀疏运动与刚性路线

测试过：

- sparse ego-flow residual；
- 两帧局部刚性/Delaunay edge strain；
- 静态标定的图划分；
- 稀疏 3D rigid-motion hypothesis；
- 运动组支持量与箱子可观测性。

结果：

- sparse ego-flow residual 是目前最强、最便宜的直接 feature-level 运动证据；
- 简化的两帧刚性和稀疏 3D hypothesis 没有产生稳定对象级分组；
- 这些负结果不能否定 Dai、DymSLAM、MVO 等完整长期/多模型方法，只能否定当前简化实现。

## 五、当前轻量几何方法的详细原理

### 5.1 准确名称

> **RGB-D/SE(3) ego-motion-compensated sparse LK flow residual filtering**  
> 基于 RGB-D/SE(3) 相机自运动补偿的稀疏 LK 光流残差过滤。

它不是：

- 原始 LK 位移阈值；
- FlowFusion 复现；
- SInDSLAM 复现；
- 完整未知动态对象检测器；
- 像素级动态 mask 生成器。

### 5.2 参考帧与调用时机

参考数据来自上一张成功跟踪帧：

```text
reference gray
reference CV_32F meter depth
reference final Tcw
reference timestamp/frame id
```

当前帧先走 ORB-SLAM2 原有初始跟踪：

```text
TrackWithMotionModel / TrackReferenceKeyFrame / Relocalization
→ 第一次原有 PoseOptimization
→ 得到当前 initial Tcw
→ 运行 sparse ego-flow measurement
→ TrackLocalMap
```

参考帧使用 final pose，当前帧使用 initial pose。当前方法依赖初始位姿，但没有新增优化次数。

### 5.3 LK 实际对应

对当前 ORB 特征：

\[
\mathbf u_t = \text{Frame::mvKeys}[i].pt,
\]

用 backward pyramidal LK 得到其在上一成功帧中的对应：

\[
\mathbf u_r
=
\operatorname{LK}(I_t,I_r,\mathbf u_t).
\]

再做 forward LK：

\[
\mathbf u_t^{fb}
=
\operatorname{LK}(I_r,I_t,\mathbf u_r),
\]

并计算 forward-backward error：

\[
e_{fb}=\|\mathbf u_t^{fb}-\mathbf u_t\|_2.
\]

当前只接受：

\[
e_{fb}\le 0.25\ \text{pixel}.
\]

这个检查只表示 LK 对应具有前后向一致性，不表示该点动态。

### 5.4 静态场景的相机诱导光流

在参考像素读取米制深度：

\[
d_r=D_r(\mathbf u_r).
\]

反投影：

\[
\mathbf X_r
=
\pi^{-1}(\mathbf u_r,d_r).
\]

ORB-SLAM2 位姿是世界到相机的 \(T_{cw}\)。参考帧到当前帧的相对变换为：

\[
T_{t\leftarrow r}
=
T_{cw,t}^{(0)}
\left(T_{cw,r}^{\mathrm{final}}\right)^{-1}.
\]

若该点属于静态世界，它在当前帧的预测位置为：

\[
\widehat{\mathbf u}_t
=
\pi\left(T_{t\leftarrow r}\mathbf X_r\right).
\]

实际观测光流：

\[
\mathbf f_{obs}=\mathbf u_t-\mathbf u_r.
\]

相机诱导光流：

\[
\mathbf f_{ego}=\widehat{\mathbf u}_t-\mathbf u_r.
\]

最终 residual：

\[
\mathbf f_{res}
=
\mathbf f_{obs}-\mathbf f_{ego}
=
\mathbf u_t-\widehat{\mathbf u}_t.
\]

残差幅值：

\[
r_i=\|\mathbf f_{res,i}\|_2.
\]

因此，相机运动造成的大光流不会自动被视为动态：只要静态三维投影能够解释它，\(r_i\) 仍应较小。

### 5.5 有效性与 no-evidence

只有以下条件全部满足，才得到 `measured` evidence：

- backward LK 成功；
- forward LK 成功；
- forward-backward error 有效；
- reference depth 有效；
- 三维点在当前相机前方；
- 投影位于图像内；
- RGB、depth、mask、ORB 和几何投影位于共同针孔域；
- 当前和参考位姿有效。

其余状态明确记录为：

```text
reference_unavailable
lk_invalid
depth_invalid
projection_invalid
domain_invalid
```

这些状态表示“没有几何证据”，不能解释成静态。

### 5.6 帧内尺度与 q 候选

当前代码对全帧质量合格的 residual 取中位数，并构造尺度：

\[
s_t
=
\max\left(
0.001,
1.4826\cdot \operatorname{median}_i(r_i)
\right).
\]

注意：这是本项目的中位数尺度改造，不是 Li & Lee 原始三维 Student-t 权重，也不是严格复现 MAD 公式。

归一化残差：

\[
q_i=\frac{r_i}{s_t}.
\]

冻结候选工作点：

\[
q_i\ge 10.
\]

此外：

- 至少需要 20 个尺度样本；
- semantic mask 内特征不重复进入几何候选；
- `q=10` 是项目实验工作点，不是论文通用阈值；
- 应称为“高残差候选”，不能称为已验证的“高置信动态特征”。

### 5.7 G1-F1：Tracking 关联过滤

准确位置：

```text
TrackLocalMap()
→ SearchLocalPoints()
→ 既有语义过滤
→ G1-F1 将候选的 mvpMapPoints[i] 置空
→ 第二次原有 PoseOptimization()
```

G1-F1 保护的是 SearchLocalPoints 后的最终局部地图位姿优化。它不能回溯消除候选对第一次初始位姿的影响。

### 5.8 G1-M1：MapPoint 写入保护

若 tracking 与 mapping 安全条件都通过：

```text
candidate
→ 写入当前 Frame::mvbDynamic
→ RGB-D MapPoint admission 跳过该 feature/depth
→ KeyFrame 保存 dynamic flag
→ 既有 dynamic endpoint guard 生效
```

它只阻止当前已判候选创建新的稀疏 MapPoint，不能清理历史动态 MapPoint，也不处理完整深度图。

### 5.9 Fail-open 安全条件

以下情况整帧不做几何删除：

- 参考帧、坐标域或尺度无效；
- 尺度支持少于 20；
- 位于重定位后的保护窗口；
- MapPoint 关联少于 30；
- 删除后剩余关联少于 30；
- 候选关联超过当前关联的 5%；
- mapping candidate feature/depth 比例超过 5%；
- mapping 后剩余有效深度特征少于 100；
- feature/sample/vector 尺寸不一致。

这些是工程安全设计，不是动态检测算法贡献。

## 六、为什么没有把所有论文拼进工程

### 6.1 候选库是“决策空间”，不是“物料清单”

候选库用于回答：有哪些物理证据、复杂度和失败模式。它不意味着每篇论文都贡献一个可以独立拔插的函数。

很多论文的效果来自完整闭环：

```text
区域表示
↔ 运动残差
↔ 相机位姿
↔ 时序状态
↔ 地图模型
```

只摘取其中一个公式，通常不能保留论文效果。

### 6.2 方法假设互不兼容

- DynaSLAM 依赖多历史关键帧和深度数据库；
- ReFusion 依赖 TSDF 静态模型、渲染和自由空间；
- StaticFusion 依赖稠密模型和联合概率优化；
- FlowFusion 依赖稠密 PWC-Net、supervoxel 和迭代 dense VO；
- Dai 依赖长期 MapPoint 图；
- MVO/DymSLAM 需要多运动模型和 tracklet；
- V3D-SLAM 需要稳定实例点云和帧间实例身份。

它们不是同一个状态空间中的独立插件。强行拼接会产生重复位姿估计、冲突的动态定义和多个互相污染的时序状态。

### 6.3 计算量不能简单相加

若同时加入：

```text
YOLO segmentation
+ dense depth warp
+ K-means/RAG
+ dense optical flow
+ graph optimization
+ temporal mask propagation
+ TSDF/free-space
```

系统会从轻量 ORB-SLAM2 前端变成一套新的稠密动态重建系统。实时性只是其中一个问题；更大的问题是调试、复现、依赖和维护边界全部改变。

### 6.4 输出定义并不一致

不同论文输出可能是：

- 单点静态权重；
- 二值 feature label；
- 像素动态 mask；
- 几何区域概率；
- 多刚体 SE(3)；
- TSDF 中的动态/自由空间状态；
- 对象实例轨迹。

把它们简单做 OR、AND 或加权相加没有统一的概率意义，也会模糊 `unknown` 与 `static`。

### 6.5 科学归因会消失

如果一次加入十种机制，即使 ATE 改善，也无法回答：

- 哪个组件真正有效；
- 哪个组件只增加计算量；
- 哪个组件制造静态误删；
- 哪个结果属于已有论文复现，哪个属于本项目改造。

当前分阶段 shadow→filter 的价值，就是让负结果和有效组件都能被单独审计。

### 6.6 当前轻量路线是主动选择，不是忘记其他论文

当时冻结的约束是：

```text
先不改后端
先不做对象 BA
先不做 TSDF
尽量接近同步 30 FPS
优先复用 ORB-SLAM2 稀疏前端
每个新增判决先 shadow 验证
```

在这些约束下，sparse ego-flow 是成本最低、能直接绑定当前 ORB feature、又有明确物理和文献依据的路线。

实验结果表明，这个选择成功解决了“如何低成本产生并接入运动不一致候选”，但没有解决“如何从候选恢复可靠未知动态对象”。这不是候选库无用，而是当前轻量约束决定了只实现其中一条支线。

## 七、当前实验结果

### 7.1 TUM `fr3_walking_xyz`

| 模式                | 轨迹      | ATE RMSE   | RPE RMSE | FPS    |
| ----------------- | -------:| ----------:| --------:| ------:|
| ORB baseline（首轮）  | 816/827 | 0.926133 m | 0.078290 | 28.423 |
| semantic-only     | 827/827 | 0.019142 m | 0.011836 | 28.261 |
| geometry-only（首轮） | 587/827 | 0.533014 m | 0.096267 | 28.506 |
| semantic+geometry | 827/827 | 0.018693 m | 0.012298 | 27.083 |

同轮 semantic+geometry 相对 semantic-only：

```text
ATE  -2.35%（改善；仅单轮）
RPE  +3.90%（变差）
FPS  -4.17%
```

三次正式 semantic-only ATE 中位数为 `0.016477 m`，裸 ORB 中位数为 `0.730574 m`。语义分支是 TUM walking 上明确、可重复的主要收益来源。

相关文章在 `fr3/walking_xyz` 上的 semantic→combined 几何增量：

| 方法         | semantic-only | semantic+geometry | ATE 增量         |
| ---------- | -------------:| -----------------:| --------------:|
| DynaSLAM   | 0.0150        | 0.0150            | 0%             |
| Ji 2021    | 0.0217        | 0.0194            | 改善 10.6%       |
| DGS-SLAM   | 0.0166        | 0.0156            | 改善 6.0%        |
| DT-SLAM 同轮 | 0.019142      | 0.018693          | 改善 2.35%，未证明稳定 |

结论：TUM walking 上完整系统已接近 1.5–2 cm 常见水平，几何相对强语义基线的剩余空间本来就很小。

| semantic-only     | 0.152247 m | 0.051377 | 29.707 | 778/778 |
| semantic+geometry | 0.178114 m | 0.045061 | 29.544 | 778/778 |

相对变化：

## 九、下一方向的含义

如果继续追求未知动态箱子，不应继续为 q10 添加邻域、面积或连续帧小补丁。当前缺失的是有独立文献和对象假设支撑的中间层：

```text
低层 motion evidence
→ 几何区域或共同运动模型
→ 时序确认
→ 未知动态对象候选
→ feature/depth filtering
```

可选路径：

1. 保持当前轻量路线收尾，只将其作为实验性 feature filter；
2. 将 SInDSLAM 开源系统作为独立重型路线审计和复现，而不是悄悄拼入当前模块；
3. 若走稀疏多运动路线，则需要更完整的 tracklet、多模型拟合和时序身份，而不是单点 q 阈值。

任何后续升级都应先明确：它是论文复现、受论文启发的改造，还是本项目工程设计，并重新测量 ATE/RPE/FPS、静态误删和未知箱子对象命中。

## 十二、为什么 Shadow 代码量远大于当前 LK 主路径

“当前方法是一条轻量稀疏 LK 支线”描述的是默认实验运行时真正参与判决的算法，
不代表仓库中只实现过 LK。当前代码量是整个几何研究过程的累计资产。

### 12.1 核心文件规模

截至本报告：

| 文件                                      | 行数   | 主要内容                                                                                  |
| --------------------------------------- | ----:| ------------------------------------------------------------------------------------- |
| `include/GeometricDynamicDetector.h`    | 738  | 所有几何结果、状态、统计和接口结构                                                                     |
| `src/GeometricDynamicDetector.cc`       | 3872 | depth warp、多参考、金字塔、sparse flow、rigidity、rigid hypothesis、region partition/aggregation |
| `include/JiGeometryBaseline.h`          | 126  | Ji baseline 接口与统计                                                                     |
| `src/JiGeometryBaseline.cc`             | 472  | 3D K-means 与簇级重投影 shadow                                                              |
| `Examples/RGB-D/geometric_warp_test.cc` | 1852 | 几何、状态、不变量和回归测试                                                                        |

`GeometricDynamicDetector.h/.cc` 本身就是 4610 行。与原始 ORB-SLAM2 相比，
当前 `Tracking.h/.cc` 还增加了数千行配置、调用、CSV、GT 分支、安全过滤和
诊断保存代码；其中也包含语义接入，不能把全部增量都算作某一个几何算法。

此外，几何/稀疏流/Bonn/运动分组相关 Python 审计工具合计约一万行。它们不进入
在线 SLAM 二进制主路径，但负责候选选帧、CSV 不变量、区域证据、箱子覆盖、
MapPoint 生命周期和结果汇总。

### 12.2 `GeometricDynamicDetector` 中保留的研究模块

按当前源码大致分为：

1. **公共几何与不确定性工具**
   
   - 深度、位姿、内参验证；
   - 反投影/投影；
   - axial depth uncertainty；
   - percentile、计时和状态统计。

2. **G0 单参考深度证据**
   
   - dense forward warp；
   - z-buffer；
   - signed residual；
   - positive/negative/consistent/unknown；
   - depth-region growing。

3. **G2 多参考与性能近似**
   
   - 多参考证据投票；
   - recent/covisibility reference selection；
   - dense、grid-depth、ORB-depth sampling；
   - boundary-aware pyramid；
   - feature sampling 与覆盖统计。

4. **当前稀疏 ego-flow 路径**
   
   - backward/forward PyrLK；
   - RGB-D/SE(3) ego projection；
   - SLAM/GT residual；
   - evidence state；
   - median scale 与 q candidate。

5. **局部刚性与不确定性 shadow**
   
   - 两帧三维节点；
   - Delaunay/局部边；
   - edge-length change；
   - 深度噪声归一化；
   - node/edge/frame diagnostics。

6. **稀疏三维刚体假设 shadow**
   
   - 局部 3D motion hypothesis；
   - 支持点、排斥点和状态验证；
   - 运动组可行性统计。

7. **区域表示 shadow**
   
   - depth-discontinuity partition；
   - full/low-resolution region；
   - 多参考证据按区域聚合；
   - boundary/invalid-depth risk diagnostics。

8. **Ji 2021 独立 baseline**
   
   - 固定 K 的 3D K-means；
   - cluster label；
   - feature/map-point reprojection statistics；
   - deterministic random seed 与 debug output。

### 12.3 `Tracking` 中的大量代码是什么

`Tracking` 的几何增量不只是调用 `ComputeSparseEgoFlow()`，还包括：

- 几十项 YAML 与环境变量读取和互斥条件检查；
- reference cache、multi-reference history 和 GT pose cache；
- 每种 shadow 的逐帧/逐 feature/逐 edge/逐 region 记录结构；
- 大量 CSV、直方图、debug image 和 timing 保存；
- counterfactual association/MapPoint admission 快照；
- G1-F1/G1-M1 fail-open 与不变量；
- MapPoint candidate 生命周期审计；
- Viewer 所需的实际移除 feature 导出；
- 关闭所有开关时保持原始 ORB-SLAM2 路径的条件分支。

其中诊断和保存逻辑的代码量往往比某一个数学核心更大，因为每个负实验都要求能
回答“输入是否有效、证据在哪里、为什么没有执行、有没有修改 SLAM 状态”。

### 12.4 当前运行到底会执行哪些

当前 `semantic+geometry` 轻量实验配置主要执行：

```text
SparseEgoFlowShadow
→ SelectSparseFlowHighResidualCandidates
→ G1-F1 tracking filter
→ G1-M1 mapping filter
→ 可选 CSV/Viewer diagnostics
```

以下模块在当前配置中默认关闭，不参与每帧结果：

```text
single-reference depth warp
multi-reference depth evidence
region growing/partition/aggregation
local rigidity
rigid motion hypotheses
Ji K-means baseline
counterfactual/map-quality audits
GT-pose diagnostics
```

因此，仓库中的 5000 多行不是“为了实现 LK 写了 5000 行”，而是：

> **多个有文献依据的 shadow 候选、失败实验、坐标/不确定性基础设施、真实过滤接入、可复现日志和测试的累计代码；当前轻量运行只激活其中一条子路径。**

这也意味着当前代码确实存在研究原型常见的维护负担。后续若做代码优化，应先把
“冻结但需保留的实验模块”与“正式运行模块”在文件层拆开，而不是直接删除负实验
或在尚未归档证据前重写算法。
