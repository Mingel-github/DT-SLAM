# DT-SLAM 当前语义与区域几何正式算法技术报告

日期：2026-08-06
用途：供项目成员学习当前真正参与 SLAM 的算法；不把历史 shadow 候选混入正式方法。

---

## 1. 这份报告讲什么

当前 DT-SLAM 的实际主系统可以概括为：

\[
\boxed{
\text{RGB-D ORB-SLAM2}
+\text{YOLOv8-seg 人物语义}
+\text{SInDSLAM 风格类别无关区域几何}
}
\]

两个动态分支产生不同来源的证据：

- **语义分支**：判断一个像素是否属于模型已知的 `person` 类；
- **几何分支**：判断一个区域是否存在不能由全局相机运动解释的真实图像运动，不依赖物体类别。

二者最终形成：

\[
\mathcal D_t^{feat}
=\{i\mid \text{第 }i\text{ 个 ORB 观测被语义或几何判为动态}\},
\]

以及：

\[
M_t^{depth},
\]

即用于深度建图的动态像素掩码。

本报告重点回答五个问题：

1. YOLOv8-seg 如何真正影响 ORB-SLAM2；
2. 当前类别无关几何到底计算了什么；
3. 三维聚类在当前方法中扮演什么角色；
4. 当前方法与 Ji 2021、DGS-SLAM、原始 SInDSLAM 等三维聚类方法有何区别；
5. 哪些部分已经验证有效，哪些仍然只是能力边界。

## 2. 术语和阶段代号

| 名称 | 含义 |
| --- | --- |
| ORB | Oriented FAST and Rotated BRIEF，ORB-SLAM2 使用的稀疏关键点和二进制描述子 |
| MapPoint | ORB-SLAM2 中由多帧特征观测建立的稀疏三维地图点 |
| mask | 与图像同尺寸的像素掩码；非零像素表示该分支认为需要排除的区域 |
| RAG | Region Adjacency Graph，区域邻接图 |
| DeepFlow | 当前正式几何分支使用的 CPU 稠密光流后端 |
| homography | 单个三乘三单应矩阵，用来近似当前帧与参考帧之间由相机运动造成的全局二维对应 |
| S1 | SInDSLAM 风格区域几何检测：生成类别无关动态区域 mask |
| S2 | 将 S1 动态区域映射到 ORB 特征，并真实影响 Tracking 和新 MapPoint 写入 |
| S3 | 生成动态深度 mask 和过滤后的静态深度副本，供建图使用 |
| fail-open | 过滤后静态约束不足时，Tracking 暂时恢复本帧几何候选；这是一项安全措施，不代表候选已被证明为静态 |

代码中仍保留 `ShadowEnable`、`RunSInStyleRegionShadow()` 等历史名称，因为 S1 最初在 shadow 模式下开发。**当 `RegionFeatureFilterEnable` 或 `DepthFilterEnable` 打开时，S1 输出会真实改变 `mvbDynamic` 或建图深度，因此此时整个系统不再是 shadow-only。**

历史上的单参考 depth warp、Ji 基线、稀疏 LK 高残差、局部刚性、运动分组等代码仍可用于实验和审计，但不是本报告所述的当前主几何判决。

## 3. 总体数据流

```text
RGB ───────────────────┐
                       ├─> YOLOv8-seg ─> person mask ───────────────┐
Depth ─> 坐标域统一 ───┤                                             │
                       └─> SIn风格区域几何 ─> geometry mask ────────┤
                                                                     │
RGB-D ─> ORB提取 ─> 每个ORB查询两个mask ─> mvbDynamic ───────────────┤
                                                                     │
                         ┌─> Tracking匹配和当前帧位姿优化前排除       │
                         ├─> 新KeyFrame/LocalMapping拒绝创建MapPoint  │
                         └─> S3动态深度mask和staticDepthMeters <─────┘
```

系统保留四种实验模式：

1. 纯 ORB-SLAM2；
2. 仅语义；
3. 仅几何；
4. 语义与几何同时开启。

“同时开启”当前主要采用：

\[
M_t^{track}=M_t^{semantic}\lor M_t^{geometry}.
\]

这是首个系统基线，不应被理解为已经证明最优的融合规则。现有实验中，联合模式并没有在所有序列上稳定优于 geometry-only。

## 4. 输入坐标域为何必须统一

语义 mask、深度、ORB 特征和几何 mask 必须落在同一个像素域，否则“一个特征是否落入动态 mask”没有明确含义。

当前处理原则是：

- TUM3 和 Gazebo 使用其已经满足的针孔/零畸变图像域；
- Bonn 的 RGB 和注册深度都先重映射到相同的 `P=K` 无畸变针孔域；
- YOLO、ORB、深度聚类、光流和最终 mask 全部消费统一后的图像。

对于像素 \(\mathbf u=(u,v)\) 和米制深度 \(z\)，三维反投影为：

\[
\mathbf X=
\begin{bmatrix}
(u-c_x)z/f_x\\
(v-c_y)z/f_y\\
z
\end{bmatrix}.
\]

这一步不是动态算法创新，却决定三维聚类、深度边界和ORB-mask映射是否具有物理意义。

## 5. 语义分支：YOLOv8-seg如何工作

### 5.1 检测对象

当前 ONNX 模型为 YOLOv8n-seg，正式动态类别只使用 COCO 的 `person`（类别编号 0）。默认置信度门槛为 0.5，NMS 门槛为 0.45。

YOLOv8-seg不是只输出人物框。处理链包括：

```text
RGB
→ letterbox与张量转换
→ ONNX Runtime CUDA推理
→ person候选筛选
→ NMS
→ prototype mask解码
→ 恢复到原图/统一针孔域
→ 二值人物mask
```

因此，语义分支给 ORB-SLAM2 的是像素级人物区域，而不是整个矩形框。

### 5.2 同帧同步

YOLO 推理工作线程与主程序线程分开，但当前正式 baseline 不消费旧 mask。对帧序号 \(t\)：

```text
PushFrame(I_t, t)
→ WaitForMask(t)
→ 只有取得同一序号的M_sem,t后才TrackRGBD
```

所以当前语义输入的 mask age 为 0。这样做牺牲了一部分异步吞吐潜力，但避免了把上一帧人物位置错误应用到当前帧。

### 5.3 从像素mask到ORB动态状态

设第 \(i\) 个ORB关键点坐标为 \(\mathbf u_i\)，则：

\[
d_{i,t}^{semantic}
=\mathbb 1[M_t^{semantic}(\mathbf u_i)\neq0].
\]

代码分别保存：

- `mvbSemanticDynamic[i]`：仅语义来源；
- `mvbDynamic[i]`：当前供 ORB-SLAM2 消费的统一动态状态。

初始时：

\[
\texttt{mvbDynamic}=\texttt{mvbSemanticDynamic}.
\]

随后几何分支可以把额外的未知类别运动特征加入 `mvbDynamic`，但不会抹掉语义标志。

### 5.4 语义分支的能力边界

语义分支的优势是人物边界完整、GPU推理快、在TUM walking中十分稳定。它的限制是：

- `person` 表示类别先验，不等于人物当前真的在运动；
- 一个静坐者只有手在动时，整个人体仍可能被删除；
- 移动箱子、气球、推车等未配置类别不会被语义分支发现。

因此它主要负责**已知潜在动态类别的高召回处理**，不能替代类别无关几何。

## 6. 当前正式几何分支的完整原理

当前几何分支的准确名称是：

> **SInDSLAM 风格、基于三维区域重组织和稠密光流残差的类别无关动态区域检测。**

它是 clean-room 改造，不是作者 SInDSLAM 的等价复现。

### 6.1 第一步：三维K-means初始区域

对每个有效深度像素反投影为三维点 \(\mathbf X_i=(X_i,Y_i,Z_i)\)，然后求解：

\[
\min_{\{C_k,\boldsymbol\mu_k\}}
\sum_k\sum_{\mathbf X_i\in C_k}
\lVert\mathbf X_i-\boldsymbol\mu_k\rVert_2^2.
\]

正式配置中：

- 只使用 \(0<z<6\text{ m}\) 的有效深度；
- 区域数为

\[
K=\operatorname{round}\left(\frac{w h}{25600}\right),
\]

  所以640×480时为12个初始簇；
- 使用四层深度金字塔，由粗到细聚类；
- 连续帧可用上一帧标签作初始化，以减少随机变化和计算量；
- 当前正式配置每层K-means最多4次迭代、单次attempt。

这一输出只能称为**初始空间分区**。一个K-means簇可能：

- 把箱子和地面混在一起（欠分割）；
- 把同一人物或家具拆成多块（过分割）；
- 只因三维位置接近而聚在一起，并不表示共同运动。

因此当前系统绝不会在这一步直接宣称“某个K-means簇是动态对象”。

### 6.2 第二步：深度边界切分

系统先在局部邻域内计算有掩码的中值深度，以降低RGB-D孤立噪声影响。随后检查局部深度变化是否超过：

\[
\tau_D(u)=\max(0.025D(u),0.08\text{ m}).
\]

超过门槛的位置作为深度梯度边界；边界把初始K-means簇切成八邻域连通的内部区域。

这一步解决的是欠分割，例如：

```text
初始K-means：箱子前表面 + 后方墙面属于同一簇
深度突变边界：将箱子轮廓附近切开
```

但单独切分会产生很多碎片，所以还不能直接作为对象区域。

### 6.3 第三步：RAG区域合并

系统把切分后的连通区域看作图节点，用区域邻接图决定哪些碎片应重新合并。主要证据包括：

- 两区域膨胀后是否空间相邻；
- 二者是否共享由初始K-means产生的“假边界”；
- 深度直方图是否相似；
- 中心深度差是否过大；
- 区域面积排序对应的合并权重。

RAG的目的不是判断动态，而是形成比原始K-means更适合承载运动证据的空间单元：

\[
\text{初始3D簇}
\rightarrow
\text{边界切分碎片}
\rightarrow
\text{合并后的几何区域}.
\]

必须注意：当前正式路线是 **gradient-only RAG**。它没有完整保留原始 SInDSLAM 的 PEAC/AHC 平面提取和平面边缘拒绝。因此当前区域是 SIn 风格近似，不是作者完整重聚类结果。

### 6.4 第四步：计算观测稠密光流

当前正式后端在0.6倍图像尺度上运行CPU DeepFlow，再做 Variational Refinement，并恢复到原图分辨率。

系统通常用 \(t-2\) 作为参考，以增加小运动的可观测差异；如果初次光流统计显示帧间运动过大，则退回 \(t-1\)。

对当前像素 \(\mathbf u_t\)，稠密光流给出其参考帧对应位置：

\[
\mathbf u_r^{flow}.
\]

### 6.5 第五步：估计相机诱导二维运动

如果场景静止，像素运动应主要由相机运动造成。当前实现从稠密光流中按10像素网格采样对应点，并通过 `cv::RHO` 的渐进一致采样方式估计当前帧到参考帧的homography：

\[
\widehat{\mathbf u}_r^H
=\pi_H(\mathbf u_t).
\]

上一帧的区域动态状态参与样本排序：

- 上一帧较静态的区域优先用于估计homography；
- 上一帧动态区域降低权重；
- 未知区域保持中性；
- 仍保留随机扰动，避免错误先验把采样永久锁死。

这属于短时时序先验，它不是物体轨迹估计。

### 6.6 第六步：光流残差

观测光流和相机诱导光流之间的残差为：

\[
\delta(\mathbf u_t)
=\left\lVert
\mathbf u_r^{flow}-\widehat{\mathbf u}_r^H
\right\rVert_2.
\]

它回答的是：

> 当前像素的实际运动能否由估计出的全局相机运动解释？

若像素属于静态背景且homography近似充分，\(\delta\)应较小；独立运动区域通常产生较大残差。

但高残差不必然意味着动态。以下因素也会造成高残差：

- 非平面场景中的深度视差无法被单一homography完全解释；
- 光流错误、弱纹理、运动模糊；
- 遮挡和显露边界；
- 光照变化；
- 区域形成错误。

因此系统不会把每个高残差像素直接删除。

### 6.7 第七步：双阈值残差证据

残差幅值先按当前帧最大值归一化到0–255，然后同时计算Otsu和Triangle阈值。较低者形成低门槛，较高者形成高门槛，并限制到项目复现的像素残差范围。

这里需要纠正一个源码历史命名：`lowResidualMask` 实际表示

\[
\delta>\tau_{low},
\]

即“超过低门槛的中高残差支持”，不是“低残差像素”。真正的高残差核心为：

\[
H_t=\{u\mid\delta(u)>\tau_{high}\}.
\]

上一帧高残差可以加入当前中高残差支持，帮助维持短时连续性。

### 6.8 第八步：在几何区域内部作动态判决

对每个RAG区域，当前分类器按以下顺序处理：

1. 区域内高残差像素必须超过100个；
2. 高残差轮廓需满足：面积大于100且圆度大于0.2，或者面积大于2000；
3. 从合格高残差轮廓出发，只在“超过低门槛的残差支持”中进行区域约束填充；
4. 若填充超过该几何区域的50%，整区域判为动态；
5. 否则只保留被填充的局部动态部分；
6. 输出前做9×9膨胀，但正式消费者还会与有效区域相交。

因此当前系统既不是：

```text
一个高残差点 → 直接删点
```

也不是：

```text
一个簇平均残差高 → 整个簇全部删除
```

而是：

```text
高残差核心
→ 在同一几何区域内寻找中高残差支持
→ 根据填充比例决定局部动态或整区域动态
```

这使它能够表达“一个区域只有局部在运动”，也是它与简单簇级二分类的重要区别。

### 6.9 静态、动态和未知

几何输出保留三种状态：

| 状态 | 含义 |
| --- | --- |
| dynamic | 当前存在足够区域运动证据 |
| static | 在有效区域内，当前没有通过动态判决 |
| unknown | 深度无效、区域不可用、光流/历史不足或计算失败，不能作几何判断 |

`unknown`不会自动转成动态，也不应被解释为已证明静态。几何证据不可用时，S2不应用几何过滤；S3联合模式最多退回semantic-only。

## 7. S2：动态区域如何真正影响ORB-SLAM2

### 7.1 映射到ORB特征

若第 \(i\) 个ORB落在几何动态mask中：

\[
d_{i,t}^{geometry}=1.
\]

在联合模式中：

\[
\texttt{mvbDynamic}[i]
=d_{i,t}^{semantic}\lor d_{i,t}^{geometry}.
\]

### 7.2 影响Tracking的具体位置

`mvbDynamic`不是送进g2o的一个新权重，而是在优化前阻止动态观测参与匹配或清除其关联：

- ORBmatcher在BoW、投影匹配、关键帧匹配等路径跳过动态索引；
- `TrackReferenceKeyFrame()`和`TrackWithMotionModel()`在既有`PoseOptimization()`前清除动态MapPoint关联；
- `TrackLocalMap()`在`SearchLocalPoints()`后、原生`PoseOptimization()`前再次清理残留关联。

系统没有修改`Optimizer.cc`，没有增加第三次位姿优化，也没有引入对象级BA。

### 7.3 fail-open为何存在

若强遮挡场景中几何mask覆盖太多，继续过滤可能让ORB-SLAM2缺少最低匹配数。当前系统在以下阶段检查可观测性：

- 参考关键帧匹配前，最低15个；
- 运动模型匹配前，最低20个；
- 局部地图最终位姿优化前，一般最低30个，重定位附近最低50个。

如果几何新增标志使这些条件不可能满足，则当前帧Tracking暂时清除**本帧新增几何标志**并重新匹配；语义标志不撤销，也不增加额外PoseOptimization。

Tracking结束后，几何标志会恢复，用于Mapping写入否决。因此：

```text
Tracking fail-open
≠ 把候选改判为静态
≠ Mapping也允许其写入
```

### 7.4 阻止新MapPoint污染

动态状态还会在以下路径阻止创建新的稀疏MapPoint：

- RGB-D初始化；
- 新关键帧创建；
- LocalMapping中的三角化/新MapPoint生成。

这能阻断当前候选的新污染，但不会自动删除此前已经存在的历史动态MapPoint。

## 8. S3：动态深度如何用于建图

S3支持三种深度mask模式：

```text
semantic_only
geometry_only
semantic_or_geometry
```

联合模式为：

\[
M_t^{depth}
=M_t^{semantic}\lor M_t^{geometry}.
\]

过滤深度为：

\[
D_t^{static}(u)=
\begin{cases}
0,&M_t^{depth}(u)=1,\\
D_t(u),&\text{其他}.
\end{cases}
\]

关键设计是：

- ORB-SLAM2 Tracking始终使用原始深度；
- `staticDepthMeters`只供建图输出；
- 因而可以固定同一条相机轨迹，对比过滤前后地图，避免把位姿变化混入Mapping评价。

S3本身只是逐帧拒绝当前已检测到的动态深度。普通累计点云一旦写入旧观测便不会撤销，所以前端漏检仍可能形成轨迹残影。项目后来完成的固定轨迹实验说明，时间支持和OctoMap free-space更新能进一步处理历史污染，但它们目前是独立离线Mapping评价，不是在线S3主链的一部分。

## 9. 当前方法和“三维聚类动态检测”到底有什么区别

### 9.1 首先纠正一个概念

**三维K-means只是一种空间分区方法，不等于动态检测方法。**

同样的三维簇可以承载完全不同的动态证据：

- 簇内ORB重投影误差；
- 深度和亮度残差；
- 稠密光流残差；
- 地图ICP残差；
- 长期刚性一致性。

所以比较方法时必须问两个问题：

1. 区域怎样形成？
2. 动态性怎样判定？

### 9.2 Ji et al., ICRA 2021

Ji方法的主链是：

```text
深度反投影到3D
→ 固定数量K-means（论文640×480使用N=24）
→ 收集每簇中已有匹配ORB/MapPoint
→ 计算簇内平均重投影误差
→ 高误差簇中的特征不参与位姿估计
```

其核心判据可概括为：

\[
R_j=\frac{1}{m_j}\sum_{i\in C_j}
\rho\big(\|\mathbf u_i-\pi(T\mathbf P_i)\|^2\big).
\]

它与当前DT-SLAM的区别是：

| 比较项 | Ji 2021 | 当前DT-SLAM |
| --- | --- | --- |
| 初始区域 | 3D K-means | 3D K-means |
| 区域边界精修 | 无完整重聚类 | 深度梯度切分＋RAG合并 |
| 运动证据 | 簇内稀疏ORB/MapPoint重投影误差 | 全像素稠密光流减homography诱导光流 |
| 无ORB纹理区域 | 通常没有簇级运动证据 | 仍可能由稠密光流提供证据 |
| 动态输出 | 主要删除动态簇中的特征 | 可输出局部或整区域mask，同时服务特征与深度 |
| 计算特点 | K-means和簇级重投影 | 光流和区域重组织更重 |

项目已经实现和审计过Ji风格shadow baseline，但没有选择它作为当前主线。

### 9.3 DGS-SLAM

DGS-SLAM同样以三维K-means形成区域，但动态判据更复杂：

\[
r=r_{depth}+r_{intensity}+r_{spatial}+r_{prior},
\]

其中还包含相邻区域关系、历史状态和语义先验，并用自适应阈值分类区域。

它与当前DT-SLAM的区别是：

- DGS的核心是**簇级多残差融合**；
- 当前DT-SLAM的核心是**重组织区域内的稠密残余运动结构**；
- DGS语义参与阈值和历史先验，当前geometry-only本身不依赖YOLO；
- 当前语义和几何可以独立开关，简单OR只是系统基线。

DGS不能简化成“把K-means加到YOLO前面”。它的性能来自多项残差、邻接关系、语义历史和Tracking策略共同作用。

### 9.4 原始SInDSLAM

原始SInDSLAM也是从三维K-means开始，但明确认为K-means本身会欠分割和过分割，因此加入：

```text
3D K-means
→ 深度梯度边缘＋PEAC/AHC平面边缘切分
→ RAG与深度直方图合并
→ 稠密BroxFlow/DIP flow
→ homography残差
→ 区域内局部/整体动态判决
→ 时序先验
```

当前DT-SLAM借鉴的就是这条“初始聚类只是建议、运动证据必须在重聚类区域内解释”的核心结构。

但当前版本与原文仍有差别：

| 原始SInDSLAM | 当前DT-SLAM |
| --- | --- |
| 梯度边缘＋PEAC/AHC平面边缘 | 正式配置主要为gradient-only |
| 作者完整RAG/重聚类源码行为 | clean-room梯度RAG近似 |
| BroxFlow或DIP flow | CPU DeepFlow正式主路径；GPU Brox仅独立审计 |
| 论文长间隔depth refinement | 做过shadow审计，但未进入正式主链 |
| 在线OctoMap建图 | 仅完成固定轨迹离线OctoMap可行性评价 |

因此准确表述必须是“SInDSLAM风格改造”，不能写成“SInDSLAM等价复现”。

### 9.5 DetectFusion和StaticFusion为什么又不同

DetectFusion的区域主要来自深度不连续和法向一致性几何分割，未知运动证据来自当前帧与稠密静态地图的ICP残差；它依赖surfel地图和稠密配准闭环，并不是普通三维K-means前端。

StaticFusion把区域静态概率、相机运动和背景重建联合估计。区域不是一次前端分割后的固定硬判决，其效果依赖稠密模型反馈。

它们说明：区域方法能否成功，不只取决于“有没有三维聚类”，还取决于区域、运动、位姿和地图是否形成相容的闭环。

### 9.6 一句话回答

当前DT-SLAM**包含三维聚类**，但不属于“仅靠三维K-means判动态”的方法。更准确的结构是：

\[
\boxed{
\text{3D K-means区域建议}
\rightarrow
\text{边界切分与RAG重组织}
\rightarrow
\text{稠密残余运动判决}
\rightarrow
\text{ORB与深度双输出}
}
\]

## 10. 当前真实结果说明了什么

### 10.1 已知人物动态

TUM `fr3_walking_xyz` 三轮结果中：

- 纯ORB-SLAM2 ATE中位数：0.730574 m；
- semantic-only ATE中位数：0.016477 m。

这证明当前同帧YOLO人物mask在该强人物动态序列中具有稳定系统价值，但不能外推为所有场景都应删除整个人体。

### 10.2 未知移动箱子

Bonn `moving_nonobstructing_box` 严格三轮几何ON/OFF对照：

- 几何检测运行但不影响SLAM：ATE中位数0.514344 m；
- 几何mask真实参与S2：ATE中位数0.022526 m；
- RPE中位数由0.022127 m降到0.014381 m。

这证明当前区域几何在这条未知箱子序列中真实保护了定位。

### 10.3 跨场景限制

Gazebo中，近大箱子的区域覆盖较好，但远小箱子长期漏检，且背景存在非零几何mask。geometry-only没有改善本来已经较好的纯ORB轨迹。因此不能宣称当前方法已经跨域稳定检测所有未知物体。

### 10.4 速度

当前CPU DeepFlow完整区域几何的端到端数据集运行约3.2–4.4 FPS。代表序列中：

- DeepFlow及残差约159–168 ms/帧；
- 初始区域约6–8 ms；
- 梯度切分约25–41 ms；
- RAG约25 ms；
- 最终区域分类约4–5 ms。

主要瓶颈是稠密光流和全图区域遍历，不是S3深度置零。

## 12. 学习时应避免的五个误解

### 误解一：YOLO线程独立，所以Tracking使用异步旧mask

错误。当前worker线程独立，但主程序等待同一帧序号的mask，正式语义baseline是同帧同步。

### 误解二：当前几何就是LK光流

错误。LK高残差是已经降级的稀疏实验基线；当前主几何使用CPU DeepFlow稠密光流、三维区域重组织和区域内残差判决。

### 误解三：当前几何没有使用三维聚类

错误。它确实以3D K-means开始，但K-means只提供初始区域，不直接决定动态。

### 误解四：几何未判动态就说明该像素静态

错误。无深度、无区域、无历史或光流失败属于unknown，不是静态证据。

### 误解五：S3已经是完整在线静态地图

错误。S3完成的是逐帧动态深度输出。时间支持和OctoMap目前仍是固定轨迹离线Mapping实验。

## 14. 最终总结

当前实际系统不是简单的“YOLO＋LK”，也不是简单的“3D K-means动态检测”。

语义分支的本质是：

\[
\text{已知人物类别的像素级先验}
\rightarrow
\text{ORB动态标志和深度mask}.
\]

几何分支的本质是：

\[
\text{3D空间初始区域}
\rightarrow
\text{深度边界与RAG重组织}
\rightarrow
\text{稠密光流与相机诱导运动之差}
\rightarrow
\text{区域内局部/整体动态判断}.
\]

系统接入的本质是：

\[
\text{语义/几何动态证据}
\rightarrow
\mathcal D_t^{feat}
\rightarrow
\text{Tracking与新MapPoint保护},
\]

同时：

\[
\text{语义/几何动态区域}
\rightarrow
M_t^{depth}
\rightarrow
\text{静态深度与长期地图处理}.
\]

它已经在TUM人物和Bonn未知箱子上形成真实正结果，但仍有三个不能回避的限制：远小/低纹理未知对象的跨域可靠性不足、CPU区域几何只有约3–4 FPS、核心检测结构主要来自SInDSLAM风格改造而非全新的动态检测理论。
