# DT-SLAM 当前成果、已解决问题与能力边界——GPT 同步报告

日期：2026-08-07
用途：供 ChatGPT 或其他审阅者快速理解当前正式系统、关键数据、已解决问题、解决机制及未完成工作。
说明：本文优先记录已经真实参与 Tracking 或 Mapping 的链路；历史 shadow 试验只在解释路线选择时简述。

## 1. 项目目标

项目目标不是只给 ORB-SLAM2 增加一个动态点阈值，而是在 RGB-D SLAM 中同时处理：

```text
YOLOv8-seg：处理 person 等已知动态类别
+
类别无关区域几何：处理移动箱子等语义未建模对象
→
动态 ORB 特征集合 + 动态深度区域
```

两个输出分别服务于：

1. Tracking：减少动态特征对位姿估计的影响；
2. Sparse Mapping：阻止动态特征创建新的 MapPoint；
3. Dense Mapping：减少人物、箱子等动态深度在长期地图中的重影和轨迹残留。

工程范围保持不变：没有修改 `Optimizer.cc` 或 g2o 代价函数，没有增加第三次位姿优化，没有估计物体轨迹或对象级 BA。

## 2. 当前真正使用的系统链路

### 2.1 语义分支

当前语义分支为同步 YOLOv8-seg：

```text
RGB
→ YOLOv8-seg CUDA 推理
→ person mask
→ 映射到当前 ORB 特征和深度域
→ Tracking / MapPoint 写入 / S3 深度过滤
```

RGB、depth、语义 mask 与几何 mask位于相同针孔坐标域。正式运行中语义 mask age 为0，即使用的是同一帧结果。

### 2.2 类别无关区域几何分支

当前正式几何不是早期 LK 点级规则，而是 clean-room SInDSLAM 风格区域链：

```text
RGB-D
→ 多尺度 3D 深度初始聚类
→ 深度梯度边界切分
→ RAG（区域邻接图）与深度分布合并
→ CPU DeepFlow 稠密光流
→ homography 相机运动补偿
→ 区域内高/低残差判决
→ 上一帧状态先验
→ geometry mask
```

它借鉴 SInDSLAM 的区域、稠密光流残差和短时时序结构，但不是作者源码的等价复制：当前正式配置没有完整 PEAC/AHC 平面边缘，使用 gradient-only RAG 和 CPU DeepFlow。

### 2.3 S2：Tracking 与稀疏 MapPoint 控制

几何 mask 已经真实影响 ORB-SLAM2：

- 动态 ORB 在匹配入口被跳过；
- `SearchLocalPoints()` 后、原生 `PoseOptimization()` 前清除可能残留的动态关联；
- RGB-D 初始化、关键帧创建和 LocalMapping 创建新 MapPoint时拒绝动态特征；
- 保留 ORB-SLAM2 原生优化次数与后端结构。

### 2.4 Tracking fail-open（安全恢复）

强遮挡时，正确删除大面积动态前景也可能使静态匹配不足。当前系统在 ORB-SLAM2 原生匹配条件即将失败时：

```text
只恢复本帧 geometry 标记的 Tracking 特征
保留 semantic 标记
Tracking 结束后恢复 geometry Mapping 写入否决
```

这是一项定位安全机制，不表示被恢复特征已经被证明为静态。

### 2.5 S3：Mapping侧动态深度输出

S3输出：

```text
dynamicDepthMask
staticDepthMeters（动态位置写0的深度副本）
```

Tracking始终使用原始深度，所以能够在同一相机轨迹上比较过滤前后的地图。S3不会改变 ATE；不同运行之间的小幅 ATE差异属于底层运行波动。

### 2.6 离线长期地图对照

当前完成了固定轨迹上的两类 Mapping可行性实验：

1. 时间支持：体素至少被3帧或8帧未屏蔽深度端点命中后才进入地图；
2. OctoMap：使用标准 occupied/free/unknown概率更新，允许后续自由空间射线撤销旧占用。

这两项目前均为离线固定轨迹实验，还没有接成正式在线 Mapping线程。

## 3. 关键正式结果

ATE（Absolute Trajectory Error）是全局绝对轨迹误差；RPE（Relative Pose Error）是相邻帧相对位姿误差；单位均为米，越低越好。

### 3.1 已知人物动态：TUM `fr3/walking_xyz`

三轮中位数：

| 模式 | ATE RMSE | RPE RMSE | 结论 |
| --- | ---: | ---: | --- |
| 纯 ORB-SLAM2 | 0.730574 | 0.025407 | 人物动态严重破坏原始定位 |
| 仅 YOLO语义 | 0.016477 | 0.011876 | 已知人物动态得到稳定处理 |

语义分支在该序列中把 ATE从约73 cm降到约1.65 cm，并保持接近数据集帧率。该结果跨三轮重复，是当前最稳定的已知类别证据。

### 3.2 未知移动箱子：Bonn `moving_nonobstructing_box`

几何 detector在 ON/OFF 中都运行，只控制几何 mask是否真正影响 ORB-SLAM2。三轮中位数：

| 模式 | ATE RMSE | RPE RMSE | 轨迹完整性 |
| --- | ---: | ---: | ---: |
| 几何检测运行，但不进入SLAM | 0.514344 | 0.022127 | 778/778 |
| S2区域几何真实参与过滤 | 0.022526 | 0.014381 | 778/778 |

三轮开启后的ATE均在2.2–2.3 cm，关闭时为45.2–54.8 cm。这证明当前区域几何在该未知箱子序列中具有可重复的真实定位收益。

这不能外推成“所有未知物体都已解决”，也不能由 ATE直接推出逐像素 mask准确。

### 3.3 强遮挡箱子与 fail-open

Bonn `moving_obstructing_box`：

| 版本 | ATE RMSE | RPE RMSE | Tracking OK / LOST |
| --- | ---: | ---: | ---: |
| 几何过滤关闭 | 0.546996 | 0.019121 | 589 / 0 |
| 旧S2，仅按剩余特征总数保护 | 0.177218（只评价截断轨迹） | 0.081901 | 389 / 200 |
| S2加入 ORB原生匹配阶段保护 | 0.245857 | 0.016536 | 589 / 0 |

解决内容：旧版在强遮挡中发生200帧 LOST；新增的匹配阶段 fail-open触发1次，恢复完整589帧轨迹，同时仍保留一定 ATE/RPE改善。

不能把 `0.177218 m`与完整轨迹直接比较，因为它只评价成功输出的子段；新版本 `0.245857 m`才是完整轨迹结果。

### 3.4 六序列第一轮系统评价

第一轮覆盖 TUM walking、sitting、真静态 fr1/xyz，以及 Bonn非遮挡箱子、强遮挡箱子和静态 close/far，共24次四模式运行。

主要事实：

- TUM walking：几何与联合模式约1.45 cm ATE；
- Bonn非遮挡箱子：geometry-only约2.07 cm ATE；
- Bonn强遮挡箱子：geometry-only约29.1 cm，收益明显弱于非遮挡场景；
- TUM fr1/xyz和Bonn静态 close/far中，第一轮没有明显定位退化；
- 语义＋几何简单OR并未稳定优于geometry-only或semantic-only。

这些六序列数值主要为单轮，用于范围检查；强结论优先采用上述三轮或严格ON/OFF结果。

### 3.5 AWS Small House正式仿真

新仿真包含人物与0.5 m/s匀速往返箱子，用户人工驾驶TurtleBot3，6328帧、约316.6秒。该场景比旧重复砖墙回廊具有更丰富和更分散的静态特征。

| 模式 | ATE RMSE | RPE RMSE | 轨迹覆盖率 | 实际FPS |
| --- | ---: | ---: | ---: | ---: |
| 纯ORB-SLAM2 | 0.059334 | 0.005624 | 94.82% | 19.94 |
| 仅语义 | **0.055089** | **0.004836** | 96.19% | 19.94 |
| 仅几何 | 0.056881 | 0.006505 | 97.09% | 4.57 |
| 语义＋几何 | 0.057982 | 0.005938 | **97.42%** | 4.38 |

客观解释：

- 新场景消除了旧回廊中的米级全局灾难，但路线和地图同时改变，不能把改善归因于某一个算法模块；
- 仅语义在本轮 ATE/RPE最好；
- 几何提高轨迹覆盖率并略降 ATE，但RPE变差，不能宣称稳定定位改善；
- 简单语义OR几何没有优于仅语义；
- 这是单轮完整序列，毫米级差异需考虑ORB-SLAM2运行波动。

## 4. 移动箱子伪影是怎样被处理的

### 4.1 原问题

普通累计点云只有“看见深度端点就永久加入”这一种动作。箱子移动经过不同位置时，每个位置都会被永久留下，所以最终出现连续箱子轨迹。

逐帧S3能够减少错误写入，但Gazebo远小箱子存在漏检，S3后直接累计仍保留大量轨迹。因此，伪影没有仅靠前端detector解决。

### 4.2 固定轨迹实验

使用旧Gazebo箱子600帧片段、同一条纯ORB-SLAM2轨迹、299个采样帧、10 cm体素，得到：

| Mapping方式 | 箱子残影候选保留率 | 持续非箱子结构保留proxy |
| --- | ---: | ---: |
| 普通端点永久累计 | 100% | 100% |
| 至少3帧支持，不用S3 | 26.65% | 100%（≥3帧参考） |
| 至少8帧支持，不用S3 | 6.69% | 100%（≥8帧参考） |
| OctoMap，不用动态mask | 2.39% | 69.88%（≥8帧参考） |
| S3直接累计 | 75.17% | 99.43%（≥3帧参考） |
| S3＋至少3帧 | 14.71% | 97.49%（≥3帧参考） |
| S3＋至少8帧 | **0%** | 94.48%（≥8帧参考） |
| S3＋OctoMap | **0%** | 69.60%（≥8帧参考） |

### 4.3 两种清理机制

`S3＋至少8帧`：

- S3先拒绝当前检测到的动态深度；
- 剩余体素必须在至少8个采样帧中反复出现，才确认为长期结构；
- 当前箱子以0.5 m/s匀速移动，同一10 cm体素通常无法积累8次支持，所以轨迹被拒绝。

`S3＋OctoMap`：

- 深度终点提供occupied证据；
- 射线经过空间提供free证据；
- 箱子离开后，旧箱子位置被后续自由空间射线穿过，历史占用概率下降并被撤销；
- S3用于减少初始错误写入和清除概率地图剩余尾部。

1047个箱子残影候选体素中，有965个在箱子最后一次命中后被后续非箱子射线穿过，即92.17%的候选具备自由空间清理条件。这直接解释了为什么不使用动态mask的OctoMap也能把残影从100%降到2.39%。

### 4.4 能说和不能说

可以说：

> 在当前固定轨迹、匀速箱子和体素配置下，S3与时间支持或OctoMap结合，能够把最终箱子残影代理降至0%；移动箱子的历史伪影已经获得明确的离线Mapping解决方案。

不能说：

- 前端SIn detector已经完整检测箱子；S3单独仍保留75.17%；
- 8帧规则能识别所有动态物体；慢速或长时间停留物体可能通过门槛；
- OctoMap全面优于点云；它保留free/occupied/unknown和可逆历史，但当前结构保留proxy低于8帧支持点云；
- 已经完成在线实时静态地图；当前仍是固定轨迹离线审计；
- `0%`是现实逐像素真值，它是Gazebo箱体代理体素指标。

因此，箱子伪影问题的准确结论是：

```text
逐帧前端过滤：减少错误写入，但存在漏检
+
地图端时间支持/自由空间更新：拒绝或撤销历史污染
→
当前Gazebo固定轨迹中的最终箱子轨迹可被清除
```

### 4.5 AWS Small House 完整序列复核：旧结论不能直接外推

完成6328帧S3 mask导出后，使用组合模式的同一条固定轨迹、3081个采样帧、10 cm体素重新比较：

| Mapping方式 | 箱子残影代理保留率 | ≥8帧持续非箱子参考保留率 |
| --- | ---: | ---: |
| 普通端点累计 | 100% | 100% |
| 至少8帧，不用S3 | 11.60% | 100% |
| S3直接累计 | 96.35% | 99.63% |
| S3＋至少8帧 | **8.38%** | **98.17%** |
| OctoMap，不用mask | 42.43% | 76.10% |
| S3＋OctoMap | 36.31% | 74.96% |

AWS没有复现旧600帧片段中的0%。原因具有直接数据支持：AWS箱子只在约2.01 m范围内反复运动，总路程157.19 m，约合78次单程经过；旧Gazebo范围约10.02 m，只约17次单程经过。更关键的是，箱子旧体素在最后命中后被非箱子射线重新穿过的比例，由旧序列的92.17%降到AWS的5.80%。因此OctoMap缺少撤销历史occupied状态所需的后续free证据。

当前AWS中效果最好的C主要依赖至少8帧时间支持，而不是S3：不用S3已降到11.60%，加入S3后为8.38%。S3直接累计仍保留96.35%，说明当前逐帧detector对AWS箱子的独立覆盖较弱。

## 5. 已解决问题及解决方式

| 问题 | 解决方式 | 当前证据强度 |
| --- | --- | --- |
| 已知人物严重破坏Tracking | 同帧YOLOv8-seg person mask进入ORB匹配和MapPoint写入 | TUM walking三轮强证据 |
| 语义无法识别未知移动箱子 | SIn风格重聚类＋稠密flow residual形成类别无关region mask | Bonn非遮挡箱子三轮强证据 |
| 强遮挡中过滤过强导致长段LOST | 根据ORB-SLAM2原生匹配阶段条件fail-open，仅临时恢复geometry Tracking特征 | 589帧完整轨迹，单次外部验证 |
| 动态区域只影响Tracking、不保护地图 | S2 MapPoint写入否决＋S3动态深度副本 | 代码路径、CSV和Bonn点云成立 |
| Bonn人物点云出现大量重影 | S3过滤当前动态深度 | 同位姿点云统计与Viewer目视均显示减少，但仍有少量残影 |
| 旧Gazebo移动箱子留下完整运动轨迹 | S3＋多帧支持，或S3＋OctoMap自由空间反证 | 旧固定轨迹由75.17%降至0%；AWS复核表明不能跨轨迹外推 |
| AWS短路径重复移动箱子留下残影 | S3＋至少8帧时间支持 | 固定轨迹由100%降至8.38%；S3本身仅提供较小增量 |
| 旧回字走廊重复纹理导致严重全局错误 | 改用AWS Small House并重新录制更丰富场景 | 新序列不再出现米级错误；这不是回环算法修复 |
| 输入坐标域、畸变、深度尺度与GT方向不明确 | TUM/Bonn rectification、one-to-one association、短段ATE和SE(3)合法性审计 | 已完成工程验证 |

## 6. 仍未解决或尚未正式开放的内容

1. **跨场景可靠未知物体检测尚未成立**：Bonn非遮挡箱子效果强，但Gazebo远小箱子逐帧覆盖不足。
2. **mask不是像素级对象真值**：静态背景仍可能被间歇标记；ATE改善不能替代检测评价。
3. **语义与几何融合未冻结**：简单OR没有稳定优于单分支。
4. **几何速度不足**：AWS上CPU DeepFlow约156 ms/帧，完整几何约4.4–4.6 FPS。
5. **在线长期Mapping未完成**：8帧支持和OctoMap目前是固定轨迹离线可行性实验。
6. **历史错误MapPoint清理未完成**：当前主要阻止新污染，不会自动删除过去已建立的错误稀疏点。
7. **旧回廊假回环算法没有修复**：只是换用更合理仿真环境重新评价。
8. **区别于SInDSLAM的核心detector创新尚不充分**：当前贡献以clean-room实现、语义/几何系统接入、fail-open、双输出和Mapping对照为主。

## 10. 最简结论

当前DT-SLAM已经不是shadow系统：YOLO人物语义和SIn风格类别无关区域几何都已真实进入Tracking、MapPoint写入和动态深度输出。语义在TUM人物场景中稳定有效，区域几何在Bonn未知箱子场景中产生可重复的大幅定位收益，匹配阶段fail-open解决了已观察到的强遮挡长段LOST。Mapping端可以显著降低逐帧漏检造成的历史残影，但效果依赖轨迹条件：旧Gazebo中S3＋8帧或OctoMap达到0%，AWS短路径反复箱子中分别为8.38%和36.31%。AWS结果说明当前最强清理来自时间支持，S3对该箱子的独立贡献较小。剩余主要问题是几何速度、跨域对象特异性、在线长期地图和算法原创性，而不是系统链路尚未打通。
