# AWS Small House 人与箱子正式序列四模式结果

日期：2026-08-06

## 1. 本轮目的

旧 Gazebo 回字走廊存在纹理高度重复、有效物体较少和疑似错误回环等问题。旧序列的纯 ORB-SLAM2 完整轨迹 ATE RMSE 为 5.979586 m，四种模式均发生严重全局轨迹错误，因此不适合作为主要动态算法评价场景。

本轮改用 AWS Small House，并保留自动运动人物与匀速往返箱子，由用户人工驾驶 TurtleBot3。目的不是证明新地图本身是一项算法改进，而是获得更接近室内真实环境、静态特征分布更丰富的正式 RGB-D 动态序列，重新评价当前实际系统：

1. 纯 ORB-SLAM2；
2. 仅 YOLOv8-seg 人物语义；
3. 仅 SInDSLAM 风格区域几何；
4. 语义与几何取并集。

四模式均离线处理同一份原始 RGB-D 数据，正式计时关闭 Viewer。

## 3. 四种模式的含义

| 名称 | 实际动作 |
| --- | --- |
| 纯 ORB-SLAM2 | 不使用语义或几何动态信息。 |
| 仅语义 | YOLOv8-seg 检测 `person`；人物特征不参与相关 Tracking/MapPoint 写入，S3 过滤人物深度。 |
| 仅几何 | 使用当前 clean-room SIn 风格区域链：多尺度 3D 深度初始区域、深度梯度切分、RAG 合并、CPU DeepFlow、homography 自运动补偿、区域残差判决和短时时序先验；S2 影响 Tracking/MapPoint，S3 过滤动态深度。它不是早期稀疏 LK 基线。 |
| 语义＋几何 | 对 Tracking/Mapping 使用 `person mask OR geometry mask`；几何过滤过强时可触发 fail-open，只恢复几何标记，语义标记仍保留。 |

所有模式沿用 ORB-SLAM2 原生优化流程；未修改 `Optimizer.cc`、g2o，也未增加第三次位姿优化。

## 4. 完整轨迹结果

ATE 为经过 SE(3) Umeyama 对齐后的绝对轨迹平移误差；RPE 为相邻输出位姿的相对平移误差。覆盖率为输出轨迹行数除以输入 6328 帧。

| 模式 | 输出位姿 | 覆盖率 | ATE RMSE | RPE RMSE | Tracking mean / median | 实际 FPS | 超过 50 ms |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 纯 ORB-SLAM2 | 6000 | 94.82% | 0.059334 m | 0.005624 m | 10.406 / 10.479 ms | 19.942 | 8 / 6328 |
| 仅语义 | 6087 | 96.19% | **0.055089 m** | **0.004836 m** | 10.830 / 10.716 ms | 19.935 | 18 / 6328 |
| 仅几何 | 6144 | 97.09% | 0.056881 m | 0.006505 m | 213.245 / 194.949 ms | 4.567 | 6328 / 6328 |
| 语义＋几何 | **6165** | **97.42%** | 0.057982 m | 0.005938 m | 212.876 / 194.333 ms | 4.377 | 6328 / 6328 |

相对纯 ORB-SLAM2 的单轮变化：

| 模式 | ATE RMSE | RPE RMSE | 覆盖率变化 |
| --- | ---: | ---: | ---: |
| 仅语义 | -7.15% | -14.01% | +1.37 个百分点 |
| 仅几何 | -4.13% | +15.67% | +2.28 个百分点 |
| 语义＋几何 | -2.28% | +5.58% | +2.61 个百分点 |

这些是每种模式各一次完整运行。ORB-SLAM2 存在随机采样和线程调度波动，而且四种轨迹覆盖的时间戳集合不同，因此不能把小幅差异写成稳定算法增益。当前可以直接得出的结果是：

1. 新 AWS 场景中四种模式都没有出现旧回字走廊的米级灾难性全局错误；但路线和环境同时变化，不能将改善全部归因于地图修改。
2. 仅语义在本轮 ATE 和 RPE 上最好，同时保持约 20 FPS。
3. 仅几何提高了输出轨迹覆盖率并小幅降低 ATE，但 RPE 变差，因此不能宣称几何稳定改善定位。
4. 语义＋几何覆盖率最高，但 ATE/RPE 均未优于仅语义；简单 OR 在本序列中没有产生额外定位收益。

### 5.2 几何分支

同一 RGB-D 输入下，两次运行的像素级几何证据总量一致：

| 项目 | 仅几何 | 语义＋几何 |
| --- | ---: | ---: |
| 非零几何区域帧 | 2491 | 2491 |

| 几何动态像素总数 | 122,826,270 | 122,826,270 |
| 几何拒绝占全部有效深度 | 6.77% | 组合后计入 union |
| 新几何动态特征标记总数 | 188,852 | 166,531 |
| fail-open 帧数 | 55 | 54 |
| fail-open 恢复的几何标记总数 | 6227 | 6032 |

组合模式在 3972 帧产生非零 union mask，共拒绝约 8.05% 的有效深度。语义与几何在有效深度上的重叠约 2.68 百万像素，说明二者确实提供互补空间证据；但“证据互补”没有在本轮转化成比仅语义更好的 ATE/RPE。

## 6. 性能归因

| 组件 | 平均耗时 |
| --- | ---: |
| GPU YOLO 语义总耗时 | 约 9.6 ms / 帧 |
| CPU DeepFlow | 约 156.0 ms / 帧 |
| 深度梯度区域切分 | 约 24.0 ms / 帧 |
| RAG 合并 | 约 9.7 ms / 帧 |
| 区域动态分类 | 约 2.5 ms / 帧 |

CPU DeepFlow 占当前几何耗时的主要部分。仅语义仍能按 20 Hz 数据速率运行，而两个几何模式都只有约 4.4–4.6 FPS，因此当前主几何链不实时。语义加入组合模式只使 4.57 FPS 降到 4.38 FPS，不是首要性能瓶颈。

## 7. 客观结论

本轮正式实验支持以下判断：

1. AWS Small House 比旧重复走廊更适合作为当前系统的仿真测试环境：纯 ORB-SLAM2 完整序列 ATE 为 5.93 cm，没有出现旧序列的米级全局错误。
2. YOLO 人物语义分支在本轮提供了最好的单轮定位结果，并保持约 20 FPS。
3. SIn 风格几何已在正式序列中真实执行区域检测、Tracking/MapPoint 控制、fail-open 和动态深度过滤；它提高轨迹覆盖率，但本轮没有形成明确定位收益。
4. 语义与几何的 mask 在空间和时间上互补，但简单 OR 不是本轮的最佳定位融合。
5. 当前区域几何约 4.5 FPS，后续若研究提速，应优先处理稠密光流和区域运行频率，而不是优化 YOLO。
6. 正式计时运行只完成 Tracking/检测/性能闭环，没有把逐帧PNG写盘计入4.38 FPS。随后使用相同配置单独完成了6328帧S3导出和固定轨迹Mapping对照；结果见本报告第10节。

## 9. 原计划与后续状态

四模式正式运行完成时冻结的后续顺序是：

1. 先为新 AWS 序列单独生成组合模式的 S3 mask/静态深度，不把磁盘写入混入正式 FPS；
2. 在固定同一条相机轨迹下比较普通累计、S3 直接累计、S3＋时间支持和 S3＋OctoMap；
3. 利用 Gazebo 静态世界或静态重放建立独立地图参考，评价 ghost、accuracy 和 completeness；
4. 若后续目标转向提速，再以当前 R0 配置为精度参照，优先研究有文献依据的低频检测＋时序传播、GPU 光流或更快稠密光流，并逐项做单变量对照。

其中第1、2项已于2026-08-07完成；第3项仍未建立严格静态世界真值；第4项暂缓。

## 10. 2026-08-07 固定轨迹 Mapping 补充结果

组合模式的完整S3导出正常处理6328/6328输入帧，其中6165帧具有有效Mapping位姿并写出动态深度mask。导出任务包含逐帧PNG和完整诊断写盘，实际吞吐3.27 FPS，不能替代第4节不写mask的正式4.38 FPS计时。

在同一条组合模式轨迹上，以每2帧取1帧、每8像素采样、10 cm体素和至少8帧支持进行离线Mapping：

| Mapping方式 | 箱子残影代理保留率 | ≥8帧持续非箱子参考保留率 |
| --- | ---: | ---: |
| 普通端点累计 | 100% | 100% |
| 至少8帧，不用S3 | 11.60% | 100% |
| S3直接累计 | 96.35% | 99.63% |
| S3＋至少8帧 | **8.38%** | **98.17%** |
| OctoMap，不用mask | 42.43% | 76.10% |
| S3＋OctoMap | 36.31% | 74.96% |

AWS箱子只在约2.01 m范围内反复运动，约合78次单程经过；箱子旧体素在最后命中后只有5.80%被后续非箱子射线重新穿过。因而OctoMap缺少撤销重复occupied状态所需的free证据。当前最强C主要来自8帧时间支持：不用S3已降至11.60%，加入S3后为8.38%；不能把该收益主要归于逐帧detector。
