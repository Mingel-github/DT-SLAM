# AWS Small House 固定轨迹离线 Mapping 对照结果

日期：2026-08-07

## 1. 实验问题

本实验使用已经完成的 AWS Small House 语义＋几何运行结果，不重新运行 Tracking，只固定同一条估计轨迹和同一组 RGB-D 输入，比较不同历史深度处理方式：

```text
A  不使用动态 mask，普通端点累计
B  S3 动态深度过滤后直接累计
C  S3 过滤后，要求同一体素至少获得 8 个采样帧支持
D  S3 过滤后，使用 OctoMap occupied/free 概率更新
```

它回答的是 Mapping 问题，不会产生四条不同 ATE。

## 2. 冻结输入与参数

- 原始序列：6328 帧；
- S3 动态深度 mask：6165 帧成功写出，163 帧因无有效 Mapping 位姿而按设计不输出；
- 离线 Mapping 实际处理：3081 个采样帧；
- 每 2 帧取 1 帧，每 8 像素采样 1 个深度；
- 体素边长：10 cm；
- 最大深度：6 m；
- 时间支持门槛：至少 8 个采样帧；
- OctoMap：`p_hit=0.7`、`p_miss=0.4`、占用阈值 0.5；
- 所有模式使用相同的组合模式 CameraTrajectory。

## 3. 主要结果

| Mapping 方式 | 占用点/体素数 | 箱子残影代理保留率 | ≥8帧持续非箱子参考保留率 |
| --- | ---: | ---: | ---: |
| 普通端点累计，不用 mask | 50,254 | 100% | 100% |
| 至少 8 帧支持，不用 S3 | 37,254 | 11.60% | 100% |
| S3 后直接累计 | 47,664 | 96.35% | 99.63% |
| S3＋至少 8 帧支持 | 36,543 | **8.38%** | **98.17%** |
| OctoMap，不用 mask | 32,426 | 42.43% | 76.10% |
| S3＋OctoMap | 31,724 | 36.31% | 74.96% |
| 箱子 oracle 过滤＋OctoMap | 32,008 | 0% | 76.11% |

`箱子残影代理`由 Gazebo 箱体轨迹和箱体尺寸定义，不是现实数据可直接获得的逐像素真值。`持续非箱子参考`仍可能含人物、位姿误差和深度噪声，也不等于严格 static completeness。

## 4. 与旧 Gazebo 结果为什么不同

AWS 与旧 Gazebo 的箱子速度都约为 0.5 m/s，但轨迹结构明显不同：

| 序列 | 箱子单程范围 | 总运动路程 | 约合单程经过次数 |
| --- | ---: | ---: | ---: |
| 旧 Gazebo | 10.02 m | 170.89 m | 17 次 |
| AWS Small House | 2.01 m | 157.19 m | 78 次 |

AWS 箱子在约 316 秒内反复通过同一条约 2 m 路径，约合 39 次完整往返。因此，同一空间区域会收到更强的重复 occupied 证据。

更关键的是自由空间重访条件：

| 序列 | 箱子旧体素在最后命中后被非箱子射线再次穿过 |
| --- | ---: |
| 旧 Gazebo | 92.17% |
| AWS Small House | **5.80%** |

OctoMap 不是动态物体检测器。它需要箱子离开后由后续射线把旧位置更新为 free。AWS 中重复 occupied 证据多，而最后一次箱子命中后的 free 反证很少，所以 `S3＋OctoMap`仍保留 36.31%，不能复现旧片段的 0%。这反映观测条件改变，不足以称为 OctoMap 实现错误。

## 5. 为什么 S3＋至少 8 帧表现最好

时间支持规则不要求相机后来重新看到 free space。它只接受在同一体素中反复成为未屏蔽深度端点的表面。静态墙面和家具容易达到 8 帧；持续移动的箱子表面在单次经过时通常只落入某个具体体素少数帧，视角和表面可见性变化又会分散其命中。

但本次收益主要来自时间支持，而不是 S3：

```text
至少8帧，不用S3：11.60%
S3＋至少8帧：       8.38%
```

S3只带来额外约 3.22 个百分点的箱子残影下降。S3直接累计仍保留 96.35%，说明当前逐帧语义＋区域几何链在 AWS 箱子上的直接覆盖很弱。不能把 C 的效果主要归因于 SIn 风格 detector。

## 6. 人物与箱子的证据边界

当前语义分支明确检测 `person`，且6328帧均获得同帧语义 mask，因此人物比未知箱子具有更直接的过滤来源。但本轮只有箱子轨迹真值，没有人物体积或逐像素真值，尚不能定量宣称人物残影已被完全解决。

因此，当前 AWS Mapping 的主要未知类别问题可以聚焦于箱子，同时保留人物语义漏检、边界误差和无有效 Mapping 输出帧等限制。

## 7. 客观结论

1. AWS 结果否定了“旧 Gazebo 中 0% 残影可以直接外推”的表述。
2. 当前 AWS 上最强的是 `S3＋至少8帧`，箱子残影代理由100%降至8.38%。
3. 当前 S3 对箱子的独立贡献较小；主要清理力量是 Mapping 端正时间支持。
4. OctoMap 的效果依赖后续 free-space 重访。AWS 只有5.80%的候选满足“最后命中后再次被穿过”，因此残影较多。
5. `S3＋至少8帧`适合作为当前离线静态点云方案，但固定8帧仍是项目工作点，不是通用动态识别规则。
6. 若后续需要验证 OctoMap 机制，应延长箱子运动路径，或让相机在箱子离开后重新观察旧区域，而不是先调概率参数。
